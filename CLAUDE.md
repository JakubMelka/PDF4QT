# CLAUDE.md

PDF4QT: a C++20 / Qt 6 PDF library, desktop applications and the command line tool PdfTool; the new unified application `PDF4QT` is being built. Single author (Jakub Melka), MIT licensed. Architecture and the reasons behind the rules: [arch/README.md](arch/README.md).

## GitHub issues

A fixed issue or implemented enhancement is recorded in [RELEASES.txt](RELEASES.txt) under `CURRENT:` (newest first) only as ` - Issue #NNN: <issue title as on GitHub>`; at release `CURRENT:` becomes a version line (`V: 1.6.0.0 14.6.2026`). Commit message: `Issue #NNN: <issue title>`.

## Build and test

A change is finished only when it builds warning-free (MSVC `/W4`) and the relevant tests pass; report the results ([AGENTS.md](AGENTS.md)).

- Configure: `cmake -B build -S . -DCMAKE_TOOLCHAIN_FILE=$VCPKG_ROOT/scripts/buildsystems/vcpkg.cmake -DCMAKE_BUILD_TYPE=Debug`, `cmake --build build -j` (Qt 6.9+); options in [arch/build.md](arch/build.md).
- This machine: `build/msvc2022_debug`, else `build/Desktop_Qt_6_11_2_MSVC2026_64bit_Release` built by a `.bat` in the scratchpad (`vcvars64.bat`, `cd /d`, `ninja <target>`) - [arch/build.md](arch/build.md).
- Tests ([arch/tests.md](arch/tests.md)): QtTest executables, `ctest` in the build dir, one binary in `<build>/usr/bin`, or one function `<exe> <function>`; Qt's `bin` on `PATH`, output by `-o result.txt,txt`; GUI tests need `QT_QPA_PLATFORM=offscreen`; `QTEST_MAIN` for any GUI type.
- A new test: `add_executable` + `add_test` in `UnitTests/CMakeLists.txt`, `pdf4qt_target_precompile_headers(<test> REUSE_FROM <donor>)` with a donor of the same Qt modules, one row in [arch/tests.md](arch/tests.md).
- A new library header with `Q_OBJECT` / `Q_GADGET` / `Q_NAMESPACE`: `#include "moc_<name>.cpp"` as the last line of its .cpp. Every source compiles without precompiled headers; a file generated by another target and read by moc / uic / rcc goes to `AUTOGEN_TARGET_DEPENDS`.
- An agent runs ASan + UBSan on Linux (WSL) once at the end of its work; valgrind, TSan, helgrind / drd run once per step by the coordinator, the whole tool corpus (`testpdf`, never in the repository) only on the owner's request; after a larger library change build with GCC too; all Linux jobs together at most 24; never edit the synced copies of the Linux trees, never wrap their scripts in another `flock` - [arch/checks.md](arch/checks.md).

## Modules ([arch/layering.md](arch/layering.md))

- `Pdf4QtLibCore` - the PDF engine without Widgets: objects, parsing, rendering, fonts, color, security, forms, annotations, optimization, XFA, OCR core, document tools ([document-model](arch/document-model.md), [rendering](arch/rendering.md), [ocr](arch/ocr.md)).
- `Pdf4QtLibWidgets` - draw widget, asynchronous page compilers, tools, annotation / form managers.
- `Pdf4QtLibGui` - shell of the old Editor and Viewer.
- `Pdf4QtLibFluent` - style and components of the GUI overhaul, Qt only ([fluent-style](arch/fluent-style.md)).
- `Pdf4QtLibMcp` - MCP server, transport and protocol only.
- `Pdf4QtLibApp` + `PDF4QT` - the new application (storage, shell, document tab, settings, tools, MCP, pages).
- Applications Editor, Viewer, PageMaster, Diff, LaunchPad, PdfTool; [plugins](arch/plugins.md); dev tools FluentGallery, CodeGenerator, JBIG2_Viewer, PdfExampleGenerator.

## Conventions ([arch/conventions.md](arch/conventions.md))

- CRLF line endings (`.desktop` LF); the MIT license header in every file; American English.
- No anonymous namespaces, no free functions: a static method of the class or of a `<Class>Helper` in the .cpp; check the generic helpers (`PDFJsonHelper`, `PDFGeometryUtils`, ...) first.
- No lambdas in Pdf4QtLibFluent, Pdf4QtLibApp, Pdf4QtLibMcp: connect to a member slot of the receiver; an unavoidable lambda has a comment why and a context object. Tests and the gallery may.
- `QPainter` state only by the RAII guards `PDFPainterStateGuard` / `PDFStylePainterGuard` (Fluent), never by hand-written `save()` / `restore()`.
- Pdf4QtLibFluent never reads a `QPalette`, colors come from the theme tokens; the palette is the leak color violet `#A000FF` - a violet pixel is a bug. Fluent works only in the GUI thread.
- Lifetime of Qt objects: emit last; after a `Q_EMIT` or foreign code survive the deletion of `this` (`QPointer`, check); a slot of `destroyed` only forgets the pointer (`PDFWatchedPointer`); never delete the sender synchronously (`deleteLater`); every connection has a context object.
- A popup by `exec()` is `new` + `QPointer`, never on the stack; a widget with nested objects has a deletion-order test; every Fluent widget has a live gallery sample (`UnitTestsFluentLifetime`); a finding of a lifetime sweep is fixed in the code. Freed memory stays readable on Windows: after a lifetime change run ASan.
- A thread hand-off the race detectors do not see gets `PDFThreadAnnotations` `happensBefore` / `happensAfter` (`TransportScope` for queued calls), a `QWaitCondition` wait is `PDFThreadAnnotations::wait`; parallel work over pages or items only via `PDFExecutionPolicy`, one asynchronous job (opening a document, a job that controls the work) may be `QtConcurrent::run` (owner 2026-11-09).
- A `QPainterPath` is never used by more threads at once; data shared by threads are plain immutable data (`PDFGlyphOutline`).
- No `Qt::DirectConnection` (nor a functor without a context) on a signal emitted in another thread; a computation reports through `PDFProgressSink` / a plain thread-safe interface, the GUI polls (`PDFProgressCounter`); a same-thread use has a comment why.
- A walk over the object graph of a PDF (outline, page / name / structure trees, fields, actions with `/Next`) keeps one visited set for the whole walk and a depth limit; its test has a cycle and a node shared by two paths.
- Tests check behavior, not coverage: expected values from the specification, never copied from a run; every new test is revert-checked (the report names the mutation); no forced coverage, no weakened assertion; time limits scale by `PDF4QT_TEST_TIMEOUT_FACTOR`.
- `Q_EMIT`, never `emit` (`QT_NO_EMIT`). `/W4` warning-free; only `/wd5054 /wd4127 /wd4702`.
- User-visible strings `tr()` (`%Ln` for counts); `.ts` only by `PDF4QT_lupdate`, never by hand. Dates, times, sizes, numbers of the new application only by `PDFAppLocale` (O17), never `QLocale()` / `QLocale::system()`.
- Tool parameter texts: `QT_TR_NOOP` in a member function with the `tr` of the class (`Q_DECLARE_TR_FUNCTIONS`, `PDFDocumentToolText`); the MCP schema stays English, the panels translate (owner 2026-11-02).
- CWG 1397: a nested class with default member initializers is never a default argument of a function of its enclosing class (GCC rejects it) - add an overload.
- Builder methods generated from `generated_code_definition.xml` are regenerated by CodeGenerator, never hand-edited. No QSettings in the new application; only Pdf4QtLibApp links SQLite; only Pdf4QtOcrTesseract includes Tesseract / Leptonica. A released database migration is never changed. No out-of-memory handling (no `catch` of `std::bad_alloc`).
- Security weaknesses outside the task go to [SECURITY_TODO.md](SECURITY_TODO.md) (phase 3), not fixed ad hoc; an item is never deleted, a fixed one gets a `Status` line (a security check of documents will use them). [NOTES.txt](NOTES.txt) lists the deliberate deviations from PDF 2.0 - check it before calling a gap a bug.
