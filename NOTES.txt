
Conformance to PDF 2.0 specification notes and tasks:

Digital signatures (issue #417):
 - Signing still rewrites the complete document. Incremental updates and preserving
   earlier digital signatures are not supported; signing again invalidates them.
 - Visible signature graphics use unrotated PDF page coordinates. Page rotation
   is applied by the viewer to both page content and signature appearance.
 - Manual interoperability checks in PDF4QT and Adobe Acrobat are still required
   for visible/invisible signatures, including rotated pages and certificate trust.

Section 7: Issues
 - 7.3.4.2 An end-of-line marker inside of a literal string is read as a line feed, as
   the specification says. Files written by PDF4QT 1.6.0.0 and older can contain a raw CR
   there (a string with a CR was not written as hexadecimal), and they read differently:
   text in UTF-16BE changes (U+010D is the bytes 01 0D, so it is read as U+010A), an
   encrypted string decrypts to other bytes, a file with such /O, /U or /ID can refuse
   its password and a file with such /UE, /OE, /Perms can fail to open, also a file with
   a CR LF in /O or /U (the value is too short). A signature stays valid, it covers the
   bytes of the file. Owner decision of 2026-11-02: no exception for these files. Newer versions write
   such a string as hexadecimal, so what they write reads back unchanged; a value read
   from an old file keeps the changed bytes, when the file is written again.
 - 7.4.7 JBIG2 decoder ammendments 1 and 2 not implemented
 - 7.6.7 Unencrypted wrapper document not implemented
 - 7.10.2 Only linear interpolation for sampled function is performed

   management system is used to convert colors
 - 8.6.5.6 No device to default color space is performed. Device color
   spaces can be set in color management system.
 - 8.6.5.8 default rendering intent is perceptual instead of relative colorimetric
 - 8.6.5.9 Black point compensation is user setting, graphic state setting
   is not respected (it is ignored)
 - 8.6.7 Overprint not implemented
 - 8.6.7 Output Preview and Ink Coverage apply the nonzero overprint mode (OPM 1)
   to a stencil mask (an image mask, 8.9.6.2) as to a fill: the mask has no
   colors of its own, it paints the current color of DeviceCMYK, which is
   "specified directly, not in a sampled image" (Table 146). The sentence "it
   shall not apply to the painting of images" is read as images with color
   samples of their own; the text does not name image masks, so the reading is
   an interpretation (fix wave of step 7 of phase 2)
 - 8.7.3.1 A tiling pattern used inside of a glyph procedure of a Type 3 font
   takes the space of the content, which shows the glyph, as the base of its
   matrix, not the glyph space (read from the code on 2026-11-25, not tested).
   A pattern matrix, which cannot be inverted, is not refused
 - 7.8.2, 8.4.2 Nested contents (a form XObject, a cell of a tiling pattern, a
   glyph procedure of a Type 3 font) share the stack of q / Q, the marked
   content stack and the level of BX / EX with the content, which uses them:
   an unbalanced Q, EMC or EX inside of one reaches the outer content; a form
   and a pattern cell also share the state of the text object (BT / ET) with
   it (read from the code on 2026-11-25; the operand stack, the current path
   of a pattern cell and the text object of a glyph procedure are separate
   since that day)
 - 8.10.2 Some form dictionary entries, in table 93, are not all being processed
 - 8.10.4 Reference XObject is not supported. Instead, proxy is displayed.

Section 9: Issues
 - 9.4.4, 9.6.2.1 The advance of a glyph of an embedded simple font is taken
   from the font program (FreeType), not from /Widths of the font dictionary.
   Deliberate until the owner tries the change on the corpus (owner decision
   QE.15 of the plan of Edit Content, 2026-11-24: another source of the widths
   changes the rendering of every document with wrong /Widths). The content
   model of Edit Content lays its text out by the widths of the dictionary
   (PDFContentTextLayout), so its canvas can differ from the rendering there.
   The other two deviations of QE.15 were fixed on 2026-11-25: the word spacing
   applies to the single-byte character code 32 only (9.3.3) and a Type 3 font
   gets the character and the word spacing
 - 9.4.4, 9.6.2.1 A character code, which has neither a glyph nor a width in
   the font dictionary, moves the text by nothing, also not by the character
   and the word spacing (a code with a width and without a glyph is advanced
   by its width and the spacings since 2026-11-25)
 - 9.6.5.2, 9.6.5.4 A name of /Differences replaces the base encoding of its
   code always (since 2026-11-25: a name without a glyph paints nothing and
   has no character). What remains: for an embedded font a code, whose name
   has no glyph, still gets the glyph of its /ToUnicode character, when
   /ToUnicode maps the code (strictly it is .notdef; it rescues documents with
   made-up glyph names); a known name, which the embedded program has only
   under another name (Euro / uni20AC), paints that glyph; an embedded
   TrueType font with only a (1, 0) "cmap" takes its glyphs by the character
   code and does not use /Differences (read from the code, not tested)
 - 9.10.2 A glyph name with a suffix or of several components (one.oldstyle,
   f_i) and a name uXXXXXX outside of the basic multilingual plane give no
   character; the names of the glyphs of a Type 3 font are not looked up in
   the glyph list for their characters (only /ToUnicode gives them)
 - 9.6.4 Glyph procedures of Type 3 fonts are processed at most 8 deep and
   never inside of themselves (a limit of the implementation against a stack
   overflow, SECURITY_TODO.md item 67); the refused glyph is not painted
 - 9.10.3 A character code mapped by /ToUnicode to more than one UTF-16 code
   unit (a ligature, a character outside of the basic multilingual plane) has
   no character in the text layout and in the extracted text (one QChar per
   glyph); PDFFont::getToUnicodeText gives its whole text (Edit Content)
 - 9.3.8 Text knockout not implemented
 - 9.5 Some type of fonts not supported yet (CIDFont, some others)
 - 9.6.2.1 Missing width is not used for missing characters
 - 9.6.4 d1 operator incorrectly doesn't ignore color/alpha operators
 - 9.7.4 CIDSystemInfo ignored in Table 115
