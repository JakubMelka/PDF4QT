# Build

    cmake -B build -S . -DCMAKE_TOOLCHAIN_FILE=$VCPKG_ROOT/scripts/buildsystems/vcpkg.cmake -DCMAKE_BUILD_TYPE=Debug
    cmake --build build -j

The vcpkg toolchain is required; Qt 6.9 is the minimum of the project. Options: `PDF4QT_BUILD_ONLY_CORE_LIBRARY` (no GUI target, no application), `PDF4QT_BUILD_TESTS` (ON), `PDF4QT_QT_ROOT` (needed when installing the Qt dependencies), `PDF4QT_INSTALL_TO_USR`, `PDF4QT_ENABLE_OCR` (Tesseract), `PDF4QT_ENABLE_PCH` (ON), `PDF4QT_ENABLE_COVERAGE`, `PDF4QT_ENABLE_VALGRIND_ANNOTATIONS` ([checks.md](checks.md)). On Linux set `VCPKG_OVERLAY_PORTS=vcpkg/overlays/linux:vcpkg/overlays/general` - the libpng of vcpkg crashes otherwise.

## Trees of the development machine

- `build/msvc2022_debug`: Ninja + MSVC debug, Qt 6.9.0 at `E:/Programming/Qt/6.9.0/msvc2022_64`.
- Without it the Qt Creator tree `build/Desktop_Qt_6_11_2_MSVC2026_64bit_Release` (Release, Qt 6.11.2, `VCPKG_MANIFEST_INSTALL=OFF`): after a change of `vcpkg.json` run by hand `vcpkg install --x-manifest-root=. --x-install-root=<build>/vcpkg_installed --overlay-ports=vcpkg/overlays/general`.
- Build by a `.bat` written to the scratchpad, which calls `vcvars64.bat`, `cd /d` into the tree and runs `ninja <target>` - nested quotes are mangled otherwise.
- Executables need Qt's `bin` on `PATH`; QtTest stdout is swallowed by some shells here, so run with `-o result.txt,txt` and read the file.

## Precompiled headers

`PDF4QT_ENABLE_PCH` precompiles the headers of Qt and of the standard library listed in [cmake/PrecompiledHeaders.cmake](../cmake/PrecompiledHeaders.cmake), chosen by measured parse times (the method is in the file) - never a header of PDF4QT or of the system (`<windows.h>`). A clean Release build went from 217 s to 138 s on 32 threads. `CMAKE_DISABLE_PRECOMPILE_HEADERS=ON` turns them off too.

- A test reuses the precompiled header of a donor with the same Qt modules (`UnitTestsPchCore`: Core, Gui; `UnitTestsPchWidgets`: + Widgets; `UnitTestsAppDocumentFixture`: + Network; `UnitTestsMcpTestClient`: Core, Network). What `<QtTest>` declares depends on `QT_GUI_LIB` / `QT_WIDGETS_LIB` / `QT_NETWORK_LIB`, and on MSVC the macros of the precompiled header win silently (`QTEST_MAIN` would create another application class), so `pdf4qt_check_pch_donors` fails the configuration for a mismatch.
- Sources used by more tests are object libraries (the fixtures). An object library does not pass its objects on: a test links every fixture it uses directly.
- Every source compiles without the precompiled headers. The valgrind tree builds without them (its prelude must precede every header) and is the guard of missing includes.

## moc and autogen

- The moc of a library header with `Q_OBJECT` / `Q_GADGET` / `Q_NAMESPACE` is compiled in its own .cpp (`#include "moc_<name>.cpp"` as its last line), not in the one big `mocs_compilation.cpp` of the target; a header without a .cpp stays there.
- `CMAKE_AUTOGEN_ORIGIN_DEPENDS` is OFF: the autogen of a target does not wait for the link of its libraries, so a file generated by another target, which moc / uic / rcc of a target reads, is named in its `AUTOGEN_TARGET_DEPENDS`.

## Translations

`.ts` files in `translations/` are regenerated by the target `PDF4QT_lupdate` and normalized to CRLF by [cmake/NormalizeTsLineEndings.cmake](../cmake/NormalizeTsLineEndings.cmake); never edited by hand. The merged `.qm` files are built by `release_translations`.
